## UC05 — Cadastrar-se

**Tabela 10 — Caso de uso UC05 — Cadastrar-se**

| Campo | Conteúdo |
| ----- | -------- |
| Identificador | UC05 |
| Ator principal | Visitante |
| Atores secundários | — |
| Pré-condições | O visitante não está autenticado |
| Pós-condições | Uma conta é criada, com perfil associado, e a sessão é iniciada |

### Fluxo principal

1. O visitante aciona a opção de cadastro.
2. O sistema exibe o formulário com nome de usuário, e-mail e senha.
3. O visitante preenche os campos e confirma.
4. O sistema valida que o nome de usuário e o e-mail ainda não estão em uso.
5. O sistema valida a senha contra as regras de robustez.
6. O sistema cria a conta, armazenando a senha como hash.
7. O sistema cria o perfil associado à conta.
8. O sistema inicia a sessão e redireciona para a listagem de textos.

### Fluxos alternativos

**A1 — Visitante já tem conta** (no passo 2)

1. O visitante aciona o vínculo para a tela de autenticação.
2. O fluxo se encerra e segue em UC06.

### Fluxos de exceção

**E1 — Nome de usuário ou e-mail já cadastrado** (no passo 4)

1. O sistema indica qual campo está em conflito.
2. O sistema reexibe o formulário preservando o que foi digitado, exceto a senha.
3. O fluxo retorna ao passo 3.

**E2 — Senha recusada** (no passo 5)

1. O sistema informa qual regra não foi atendida.
2. O fluxo retorna ao passo 3.

### Regras de negócio

- **RN06 —** A senha é armazenada com hash PBKDF2, padrão do Django. Senha em
  texto puro não existe em nenhum ponto da persistência.
- **RN07 —** A senha precisa ter no mínimo 8 caracteres, não pode ser
  inteiramente numérica, não pode constar da lista de senhas comuns do Django e
  não pode ser parecida com o nome de usuário ou o e-mail.
- **RN08 —** Toda conta criada nasce com o papel de autor. Moderador é concedido
  manualmente por quem administra a plataforma.
