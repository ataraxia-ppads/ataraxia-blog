# UC10 — Comentar post

**Tabela 11 — Caso de uso UC10 — Comentar post**

| Campo | Conteúdo |
| ----- | -------- |
| Identificador | UC10 |
| Ator principal | Autor |
| Atores secundários | Moderador |
| Pré-condições | O usuário está autenticado e o texto está publicado |
| Pós-condições | O comentário é gravado, vinculado ao texto e ao seu autor, e passa a ser exibido |

## Fluxo principal

1. O usuário autenticado lê um texto publicado.
2. O usuário escreve o comentário no formulário ao final do texto.
3. O usuário envia.
4. O sistema valida que o comentário não está vazio e respeita o tamanho máximo.
5. O sistema grava o comentário com `approved = True`, registrando autoria e data.
6. O sistema recarrega a página com o comentário visível.

## Fluxos alternativos

**A1 — Usuário não autenticado** (no passo 2)

1. O sistema exibe um convite para entrar, no lugar do formulário.
2. O fluxo se encerra.

**A2 — Comentários encerrados no texto** (no passo 2)

1. O sistema informa que o texto não aceita novos comentários.
2. O fluxo se encerra.

## Fluxos de exceção

**E1 — Comentário vazio ou longo demais** (no passo 4)

1. O sistema informa o problema.
2. O sistema reexibe o formulário preservando o texto digitado.
3. O fluxo retorna ao passo 3.

**E2 — Texto despublicado durante a escrita** (no passo 5)

1. O sistema recusa a gravação e informa que o texto não está mais disponível.
2. O fluxo se encerra.

## Regras de negócio

- **RN13 —** Comentar exige autenticação. Não há comentário anônimo.
- **RN14 —** O comentário nasce aprovado e é retirado do ar pela moderação,
  descrita em UC11. Moderação prévia exigiria alguém de plantão para que a
  discussão parecesse viva.
- **RN15 —** O corpo do comentário é tratado como texto puro na exibição.
  Nenhuma marcação enviada pelo usuário é interpretada como HTML.
- **RN16 —** O comentário mantém o vínculo com quem o escreveu, e esse vínculo
  não é editável.
